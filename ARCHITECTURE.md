# Архитектура HouseBuilder

Веб-приложение для проектирования жилья (квартира / частный дом с участком) под реалии Украины.
Стек: Vite + React + TypeScript, Three.js через React Three Fiber, Zustand (+ immer), Vitest.

## Главный принцип

**Единая модель данных (JSON) — единственный источник правды.** 2D-план, 3D-сцена, чертежи,
спецификации и сметы — чистые функции от модели. Никакое представление не хранит собственную
копию геометрии. Производные данные, лежащие в модели (контуры и площади помещений), пересчитываются
слоем мутаций при каждом изменении стен.

```
                 ┌──────────────┐
  UI-действия →  │ projectStore │ → history (undo/redo) → IndexedDB / .json
                 └──────┬───────┘
                        │ Project (JSON, мм)
     ┌────────┬─────────┼──────────┬───────────┬──────────┐
     ▼        ▼         ▼          ▼           ▼          ▼
  draw2d   view3d    cabinet     calc       rules     drawings
 (Prim2[]) (three)  (детали,   (плитка,   (проверки) (листы →
  → SVG             раскрой)   смета...)              SVG/PDF/DXF)
```

## Единицы и координаты

- Внутри модели всё в **миллиметрах** (целые/дробные числа), углы в градусах.
- План: X вправо, Y вниз (как на экране). 3D: X → X, Y плана → Z, высота → Y; масштаб 0.001 (метры).
- Отображение: мебель — мм, планы — см/м, площади — м², объёмы — м³.
- Локальная система объекта (Item): X вдоль ширины, Y вдоль глубины (y=0 — «спинка», к стене), Z вверх.

## Модель данных (`src/model/types.ts`)

```
Project
 ├─ kind: 'apartment' | 'house'
 ├─ levels: Level[]
 │    ├─ walls: Wall[]          a, b (ось), thickness, material, loadBearing, отделка сторон L/R
 │    ├─ openings: Opening[]    wallId, pos вдоль оси, тип door/window/portal, размеры
 │    ├─ rooms: Room[]          производное: polygon, area (+ имя, тип, отделка пола/потолка)
 │    ├─ items: Item[]          точечные объекты: мебель, корпуса, розетки, сантехточки, радиаторы…
 │    ├─ routes: Route[]        полилинии: кабели, трубы, воздуховоды
 │    ├─ zones: Zone[]          полигоны: тёплый пол
 │    ├─ dims: Dim[]            размерные линии
 │    └─ underlay               подложка (изображение + масштаб)
 ├─ site: Site | null          границы, рельеф, север, items/routes/zones ландшафта
 ├─ finishes: Finish[]         каталог отделочных материалов (редактируемый)
 ├─ cabinets: CabinetDesign[]  изделия корпусной мебели
 ├─ cabinetCatalog             плиты, кромки, фурнитура, параметры листа/пропила
 ├─ models: CustomModel[]      импортированные glTF/OBJ
 ├─ electrical.groups          группы и автоматы
 ├─ baseline                   «существующее состояние» стен (для проверки перепланировки)
 ├─ ruleOverrides              пользовательские правки нормативных значений
 └─ prices / reserves / stamp  цены и запасы для сметы, штамп чертежей
```

Обобщённые сущности `Item / Route / Zone` описываются **реестром видов** (`src/catalog/registry.ts`):
для каждого `kind` — слой, локализованное имя, схема параметров (по ней автоматически строится панель
свойств), габариты, 3D-примитивы (`parts`) и/или 2D-условное обозначение (`symbol`). Добавление нового
объекта в библиотеку = одна запись в реестре.

## Модули

| Каталог | Назначение |
|---|---|
| `src/model` | Типы, геометрия (vec2, полигоны), стены (стыки, объединение контуров, детекция помещений), создание проекта, демо-проект, миграции |
| `src/store` | `projectStore` (модель, транзакции, undo/redo), `uiStore` (инструмент, выделение, слои, язык), `persistence` (IndexedDB, файл .json) |
| `src/catalog` | Реестр видов объектов: мебель (50+ параметрических), инженерные точки/трассы, ландшафт; материалы стен и отделки |
| `src/cabinet` | Конструктор корпусной мебели: генерация деталей, пильные размеры с учётом кромки, фурнитура, раскрой (гильотинный), CSV, шаблоны |
| `src/calc` | Расчёты: раскладка плитки, поверхности помещений, длины кабеля, уклоны, тёплый пол, солнце/тень, смета |
| `src/rules` | `rules.json` (редактируемый справочник норм, `verified:false` по умолчанию) + проверки → список нарушений |
| `src/draw2d` | Чистые генераторы 2D-примитивов (`Prim2[]`) для каждой сущности; общий для редактора и чертежей |
| `src/editor2d` | SVG-редактор: вьюпорт, привязки, инструменты, ручки, контекстное меню |
| `src/view3d` | R3F-сцена: построители геометрии (стены с проёмами, полы, мебель, участок), орбита, прогулка от первого лица, экспорт glTF |
| `src/drawings` | Листы чертежей (план, мебель, инженерные, развёртки, разрезы, фасады) → SVG-превью / PDF (jsPDF + DejaVu Sans) / DXF |
| `src/ui` | Каркас интерфейса: панели, диалоги, свойства, слои, проблемы, смета, конструктор |
| `src/i18n` | Локализация uk/ru |
| `tests` | Vitest: расчётная логика |

## Ключевые алгоритмы

- **Стены и помещения.** Каждая стена → четырёхугольник (с подрезкой «на ус» в L-углах). Все стены
  объединяются (`polygon-clipping`), **отверстия объединения = помещения** (чистый внутренний контур,
  площадь нетто). Метаданные помещения привязаны к seed-точке и переживают правки стен.
- **Привязки.** Узлы стен → пересечения направляющих → проекция на ось стены → угол 45° → сетка.
- **3D-стены.** Профиль стены (длина × высота) с отверстиями-проёмами → экструзия на толщину; грани
  раскладываются на 3 группы материалов (сторона L, сторона R, торцы) для отдельной отделки сторон.
- **Деталировка.** Параметрическая структура корпуса → детали с готовыми размерами → пильный размер =
  готовый − толщины кромок на противоположных сторонах.
- **Раскрой.** Гильотинная упаковка (free-rect, несколько эвристик, выбирается лучшая) с пропилом,
  обпилом листа и учётом направления текстуры.
- **Чертежи.** Генератор листа выдаёт `Prim2[]` в мм бумаги; три бэкенда: SVG, PDF, DXF.

## Сохранение

- Автосохранение проекта в IndexedDB (debounce), список проектов.
- Экспорт/импорт файла проекта `.json` (вся модель, включая подложку и импортированные модели как data URL).
- Undo/redo: стек снимков модели (immer даёт структурное разделение — снимки дешёвые). Перетаскивания
  идут транзакцией: одна запись в истории на жест.

## Производительность

- 3D: геометрия мемоизируется по идентичности под-деревьев модели; примитивы объекта сливаются по
  материалам; процедурные текстуры кешируются; в режиме орбиты `frameloop="demand"`.
- 2D: SVG, примитивы на сущность мемоизируются.
