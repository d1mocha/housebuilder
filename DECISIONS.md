# Журнал решений

Формат: **вопрос → решение → почему**.

1. **Внутренние единицы?** → Миллиметры везде, перевод в см/м/м² только при отображении. → Один масштаб
   для мебели (мм) и планов; нет ошибок округления при конвертации.
2. **2D-редактор: Canvas или SVG?** → SVG. → Бесплатный hit-testing, тот же набор примитивов идёт в
   чертежи; для масштаба квартиры/дома производительности хватает.
3. **Как определять помещения?** → Объединение четырёхугольников стен (`polygon-clipping`), отверстия
   объединения = помещения. → Сразу даёт внутренний контур нетто при разных толщинах стен и
   Т-примыканиях, без планарного графа. Двери/проёмы помещение не «открывают».
4. **Отделка стены, выходящей в два помещения одной стороной?** → Отделка задаётся на сторону стены
   (L/R) целиком; чтобы развести — «Разделить стену» в контекстном меню. → Простая модель, покрывает
   большинство случаев.
5. **Локализация: ключи или инлайн?** → Инлайн-хелпер `t('укр', 'рус')`, имена каталогов — `{uk, ru}`. →
   Невозможно забыть перевод ключа, вдвое меньше кода; минус — третий язык добавлять сложнее.
6. **Множественное выделение?** → Одиночное выделение. → Экономия сложности; все операции доступны
   поштучно.
7. **Шрифт PDF с кириллицей?** → Встраиваем DejaVu Sans (свободная лицензия) в jsPDF, грузится лениво. →
   Стандартные шрифты PDF не содержат кириллицы.
8. **DXF?** → Собственный минимальный писатель ASCII DXF (LINE/CIRCLE/ARC/TEXT/POLYLINE), кириллица через
   `\U+XXXX`. → Нет тяжёлых зависимостей, открывается в AutoCAD/LibreCAD/nanoCAD.
9. **Учитывать кромку 0,4 мм в пильном размере?** → По ТЗ уменьшаем всегда; в настройках каталога есть
   порог «учитывать кромку от … мм» (по умолчанию 0). → Часть цехов не вычитает 0,4 — оставили
   возможность.
10. **Нормативные значения?** → Все в `src/rules/rules.json`, `verified:false`, источник с пометкой
    «уточнить»; пользователь может править в приложении. → Нормы Украины обновлялись, цифры нельзя
    считать проверенными.
11. **Что считать глубиной корпуса?** → `depth` — глубина корпуса (боковина вместе с накладной задней стенкой);
    накладные фасады добавляются сверху, итог показывается как «габарит с фасадами» и используется на плане. →
    Так считают мебельщики; для шкафа-купе 600 боковина = 597 + ХДФ 3.
12. **Какая кромка по умолчанию на каких торцах?** → Лицевой торец — «лицевая» кромка (2 мм), остальные
    открытые торцы — «скрытая» (0,4 мм), торцы, упирающиеся в другие детали (вкладные дно/крышка, жёсткие
    полки, перегородки), — без кромки. Любая сторона любой детали переопределяется в деталировке. → Единого
    стандарта нет; выбрали типовую практику и оставили полную ручную правку.
13. **Зазоры фасадов?** → Между соседними фасадами — заданный зазор (2 мм), от края корпуса — половина зазора. →
    Тогда между фасадами соседних модулей получается тот же зазор.
14. **Двери-купе в деталировке?** → По умолчанию полотна в алюминиевом профиле идут в спецификацию фурнитуры
    (размер двери, направляющие, ролики), а не в раскрой ЛДСП; опция «полотна из плиты» добавляет их в
    деталировку. Вычет высоты двери — параметр (зависит от системы профиля). → Размеры наполнения считает
    поставщик системы по своим таблицам.
15. **Задняя стенка больше листа?** → Автоматически делится на равные вертикальные части, выводится
    предупреждение. → Иначе шкаф 2400×2600 нельзя раскроить.
16. **Алгоритм раскроя?** → Гильотинный free-rect с перебором 48 эвристик (сортировка × оценка × способ
    деления), пропил учитывается «раздуванием» деталей. → Простая, детерминированная, дающая реально
    выполнимые на форматно-раскроечном станке карты; не оптимальна, но близка для мебельных наборов.
17. **Помещение выделять кликом по площади?** → Только кликом по подписи (название/площадь). → Клик по пустому
    месту внутри помещения нужен для панорамирования и снятия выделения.
18. **Коллизии прогулки с мебелью?** → Только со стенами (двери и проёмы проходимы, окна — нет). → Мебель
    часто стоит плотно; коллизии с ней мешали бы осмотру.
19. **Расчёт плитки?** → Сеточная раскладка от угла; плитка целая, если все 9 контрольных точек (в 0,5 мм от
    краёв) внутри поверхности, подрезанная — если хоть одна; каждая подрезка = отдельная плитка; запас 10 %. →
    Консервативно (без повторного использования обрезков) — безопасно для закупки.
20. **Пустой репозиторий без ветки по умолчанию — куда PR?** → Работа запушена в `claude/housing-design-app-s46mp6`;
    PR создать нельзя (нет базовой ветки, а пушить в другие ветки запрещено). → Отмечено в REPORT.md.
21. **Газ?** → Только точки (счётчик, точка подключения, стояк) без трасс и расчётов; предупреждение в палитре,
    в свойствах объекта и в панели норм. → Требование ТЗ: проектирование — только лицензированная организация.
22. **Длина кабеля?** → Длина трасс в плане + вертикальные опуски к приборам, стоящим в вершинах трассы
    (|высота трассы − высота прибора|), запас в %. → Простая и прозрачная оценка без 3D-трассировки.
23. **Тёплый пол?** → Длина трубы = площадь нетто / шаг + 2 подводки на контур; число контуров подбирается под
    максимальную длину из справочника; на плане рисуется «змейка». Раскладка «улиткой» влияет только на
    выбор в свойствах (геометрия не строится). → Достаточно для сметы и схемы.
24. **Рельеф?** → Отметки вершин границы участка, между ними — интерполяция обратными взвешенными расстояниями. →
    «Упрощённый рельеф» по ТЗ без редактора горизонталей.
25. **Разрезы и фасады?** → Разрез: сечение стен и перекрытий плоскостью, проёмы в секущихся стенах, отметки,
    профиль крыши; без видимых за плоскостью элементов. Фасады: ортогональные проекции стен («алгоритм
    художника») с проёмами. → Упрощённые, но получаются автоматически из модели.
26. **Крыша?** → Плоская / двускатная / вальмовая по габаритному прямоугольнику верхнего этажа. → Этап 1 требует
    этажи и перекрытия; сложные крыши вне объёма.
27. **Смета: нормы расхода?** → Кирпич 394 шт/м³, раствор 0,23 м³/м³, клей для газоблока 25 кг/м³, краска в 2 слоя —
    ориентировочные константы в `calc/estimate.ts`, помечены в смете как «ориентировочная норма». → Зависят от
    производителя; цены и запас задаёт пользователь.
28. **После завершения трассы/зоны?** → Инструмент переключается на «Выбор», объект выделен. → Сразу доступны
    свойства и ручки вершин.

## Итерация 2

29. **«В демо вся мебель за пределами квартиры» — не воспроизводится.** → В Chromium (dev и собранная версия, разные
    размеры окна) мебель стоит в комнатах. Добавлены проверка `itemsOutsideRooms`, страховка в `createDemoProject`
    (объект вне помещений не попадёт в демо), юнит- и e2e-тест. Попутно найден и исправлен реальный дефект первой
    загрузки: план не вписывался в окно 2D (обрезался). → Причину у владельца установить не удалось; тест
    гарантирует, что в модели и в DOM объекты стоят внутри контуров помещений.
30. **«Шафа-купе — комод из 6 ящиков по 770 мм».** → Так выглядит демо-шкаф (2 секции), если тип фасадов
    переключён на «Ящики»: раньше при этом в каждую секцию ставилось по 3 ящика на всю высоту. Теперь число
    ящиков подбирается под высоту фасада ≈ 200 мм, а фасад выше 400 мм даёт предупреждение; шаблон переделан
    (раздвижные двери в профиле, штанги, полки, 2 ящика по 180 мм). → Закрывает и сам шаблон, и путь, которым
    получался «комод».
31. **Раздвижные двери: что считать?** → Дверь = (проём + перехлёст × (n−1)) / n; высота = проём − вычет; наполнение
    уже и ниже двери на вычеты профиля (36 и 60 мм по умолчанию, редактируются). Наполнение из ЛДСП 10 мм идёт в
    деталировку и раскрой, профили/направляющие/ролики/шлегель — в спецификацию. → Точные вычеты зависят от
    системы профиля, поэтому все они — параметры с пометкой «сверить с таблицей».
32. **Направление текстуры детали.** → `grain: length | width | none`. Текстура листа идёт вдоль его длины; «вдоль» —
    длина детали по длине листа, «поперёк» — по ширине листа, «без» — свободный поворот. Для материалов без
    текстуры параметр не действует. → Соответствует практике цехов.
33. **Раскрой: что значит «меньше отходов»?** → Критерий: минимум листов, затем максимум делового остатка на
    последнем листе; отходы считаются без деловых остатков (до трёх прямоугольников со стороной ≥ 200 мм на лист).
    Алгоритм: гильотинные свободные прямоугольники со слиянием, прижимом к краю и полосовыми схемами + случайные
    перестановки. → Раньше детали «размазывались» по листу (кухонная тумба 1,5 м² занимала лист на 2590 мм
    длины); теперь остаётся цельный остаток > 60 % листа. Число листов на типовых изделиях не выросло.
34. **Статусы «существующее / демонтаж / новое».** → Статус есть у стен и у инженерных приборов. Материалы кладки
    считаются только для «нового»; «демонтаж» — отдельный раздел сметы (площадь по материалу, объём мусора с
    коэффициентом 1,3, приборы поштучно); демонтируемая стена исключается из помещений, 3D и коллизий, на плане —
    красным пунктиром. Отделка считается для всех помещений (при ремонте она новая). В квартире до фиксации
    существующего состояния новые стены создаются «существующими» (идёт обводка техпаспорта), после — «новыми».
    → Трассы статуса не имеют (всегда новые).
35. **Дуговые стены — как хранить?** → `wall.arc` — стрела дуги со знаком. Вся геометрия (помещения, план, 3D,
    чертежи, коллизии) работает с производной ломаной (`geomOf`): сегменты дуги — отдельные прямые стены,
    границы сегментов совпадают с краями проёмов. → Не нужно учить дугам каждый алгоритм; цена — проём на дуге
    прямой (хорда), развёртки дуговой стены состоят из граней.
36. **Чертежи: внешние размерные цепочки.** → По каждой стороне здания до трёх уровней: 1 — проёмы и простенки стен
    этой стороны, 2 — оси поперечных стен, 3 — габарит. Уровень пропускается, если на стороне нет проёмов/
    поперечных стен. Марки проёмов: одинаковые по типу и размеру — одна марка (В-n, Д-n, ПР-n) + ведомость.
37. **Режимы вместо вкладок левой панели.** → Вкладки «План / Меблі / Мережі / Ділянка» заменены режимами
    «План / Меблі / Електрика / Вода / Опалення / Ділянка». Режим задаёт набор активных слоёв: только они
    кликабельны и попадают в рамку и Ctrl+A; остальные слои приглушены (стены и помещения — основа плана —
    рисуются как есть). Выделение объекта «снаружи» (список нарушений, клик в 3D, постановка из каталога)
    само переключает режим. Смена режима сбрасывает выделение. Инструменты стен включают режим «План».
    → Так инженерная трасса физически не может перехватить клик по стене; ценой — газ и вентиляция живут
    в режиме «Опалення» (отдельные режимы под 2–3 объекта перегрузили бы панель).
38. **Перебор объектов под курсором.** → Повторный клик в ту же точку (± 5 px) без сдвига выделяет следующий
    объект под курсором; Alt+клик делает то же принудительно. Порядок — сверху вниз по отрисовке, подписи
    помещений — в конце очереди. → Перебор срабатывает при отпускании кнопки, поэтому не мешает перетаскиванию.
39. **Мультивыделение.** → `ui.multi` — список, `ui.selection` — последний (основной) объект. Рамка слева
    направо берёт объекты целиком внутри, справа налево — пересечённые (по габаритам). При групповом сдвиге
    стен концы невыделенных стен, примыкающие к выделенным (в узлах и к телу), едут следом; проёмы едут со
    стенами и сами в группе не двигаются. Панель группы показывает общие поля однотипных объектов (значение
    первого и пометка «різні», если значения расходятся); выравнивание и распределение — по габаритам объектов.
40. **Индикаторы геометрии.** → Прямой угол — в концах отрезка, примыкающих к стене (допуск 0,6°); параллель —
    ближайшая стена, не лежащая на той же прямой и «видящая» отрезок. При рисовании показываются абсолютный
    угол и угол к стене, от которой начат отрезок. Для мебели — выравнивание по краям и центрам объектов того
    же слоя (7 px), у стены сохраняется выравнивание вдоль неё.
41. **Ручка стрелы дуги.** → Вынесена в сторону от оси стены (ромб), а не в её середину: иначе перетаскивание
    стены «за середину» превращало бы её в дугу. Стрела меньше 40 мм — стена прямая.
42. **Текстуры: откуда и в каком виде.** → Только CC0: ambientCG и Poly Haven. В репозитории лежат уменьшенные
    копии (цвет 512 px, нормали 256 px), шероховатость сведена к одному числу — всего 1,6 МБ на 32 текстуры.
    Источник и лицензия каждой — в `ASSETS_LICENSES.md`; тест проверяет, что в папке нет «лишних» файлов.
    → Реалистичность против размера репозитория и скорости загрузки: 512 px хватает для интерьера на экране.
43. **Обои «нескольких стилей» при скудном выборе CC0-обоев.** → На ambientCG обои только под покраску, поэтому
    узорные стили взяты из CC0-тканей Poly Haven (жаккард «дамаск», клетка, лён, рогожка). Часть текстур
    обесцвечена и нормирована («тонируемые») — цвет задаёт материал, так что одна текстура даёт любую палитру.
44. **Доски и плитка: формат из материала, рисунок из текстуры.** → Для ламината, паркетной доски, плитки и
    керамогранита раскладка рисуется по размерам элемента из материала, а каждая доска/плитка заполняется
    своим случайным фрагментом текстуры (волокна — вдоль длинной стороны). Текстуры с готовым рисунком укладки
    (паркет «ёлочка», «плетёнка») кладутся как есть — у таких материалов нет размеров элемента.
    → Раскладка в 3D совпадает с расчётом количества; цена — без карты нормалей на составных покрытиях.
45. **Единица цены материала.** → Обои — за рулон, краска — за литр, штукатурка — за кг, остальное — за м².
    В смете цена пересчитывается в единицу строки (упаковка ламината = цена м² × площадь упаковки, погонный
    метр линолеума = цена м² × ширина рулона). Цена, введённая в самой смете, важнее цены материала.
46. **Расчёт обоев.** → Полотно = высота помещения + 100 мм на подрезку, округлённое вверх до целого числа
    раппортов; полотен из рулона = ⌊длина рулона / полотно⌋; полотна = ⌈длина стен / ширина рулона⌉ по
    каждому помещению (двери и проёмы от пола вычитаются, окна — нет). В смете рулоны суммируются долями,
    чтобы остаток рулона шёл в соседнее помещение; запас раздела «Шпалери» — 5 %.
47. **Расчёт линолеума.** → Полотна на всю длину габарита помещения + 100 мм; из двух направлений раскатки
    берётся то, где меньше стыков, при равенстве — меньше метраж. Результат — погонные метры рулона.
    → Для Г-образных комнат это оценка сверху (по габариту).
48. **«Товар из магазина».** → Материал с полями `shopUrl / shopTitle / shopSku`. Приложение хранит ссылку и
    открывает её в новой вкладке (только http/https, `rel="noopener noreferrer"`); никаких запросов к сайту
    магазина нет — это проверяется e2e (ни одного внешнего запроса) и unit-тестом (в коде нет fetch/XHR, кроме
    загрузки встроенного шрифта PDF). Фото товара пользователь добавляет сам, оно уменьшается до 640 px и
    хранится в файле проекта.
49. **Декоры ЛДСП.** → У плиты есть `textureId`; волокна текстуры идут вдоль длины листа. Ось волокон детали в
    3D выводится из её габаритов и поля «напрямок текстури» (вдоль длины / поперёк), то есть 3D показывает то
    же, что учитывает раскрой. Фасады с заданным цветом (крашеный МДФ) рисуются без декора.
50. **Миниатюры каталога.** → Рендерятся в браузере из тех же параметрических моделей одним скрытым
    WebGL-рендерером (160 px, по одной за тик, кеш в памяти); модуль грузится отдельно от основного кода.
    Для инженерных точек миниатюра — условное обозначение с плана, для трасс и зон — образец линии/заливки.
    → Картинки не нужно хранить и обновлять вручную: изменилась модель — изменилась миниатюра.
51. **Подсказки.** → Одна карточка внизу холста: текст зависит от инструмента, а для «Вибору» — от режима
    (и от группового выделения). «Зрозуміло» скрывает одну подсказку, «Не показувати більше» — все;
    включить обратно можно в справке. e2e-сценарии по умолчанию запускаются с отключёнными подсказками,
    чтобы карточка не перехватывала клики по нижней части плана.
52. **Инженерные сети в 3D.** → По умолчанию скрыты трассы и зоны (кабели, трубы, тёплый пол) — в интерьере
    они в стенах и стяжке; приборы (розетки, выключатели, радиаторы, светильники) остаются. Кнопка «Мережі»
    показывает сети.
53. **Свет и тени в 3D.** → В режиме орбиты — один направленный источник с мягкими тенями (карта 2048,
    область — по габариту здания) плюс заполняющий свет; кнопка «Тіні» отключает. В прогулке потолок закрыл бы
    верхний свет, поэтому помещения освещаются точечными источниками под потолком (до 10), тени отключены.
    На участке с включённым солнцем тени даёт солнце, как раньше.
54. **Подписи в 3D.** → Спрайты с текстом постоянного экранного размера (three.js), а не DOM-слой (`Html` из
    drei): DOM-слой при закрытии диалога давал ошибку React 19 «removeChild». Результат рулетки дублируется
    обычным текстом в панели 3D-вида.
55. **Выбор детали в конструкторе.** → Предпросмотр строит отдельный меш на деталь (ключ детали в `userData`).
    Щелчок выделяет деталь оранжевым контуром и показывает её размеры; кнопка «у деталюванні →» открывает
    вкладку деталировки с подсвеченной и прокрученной в видимую область строкой. Щелчок по строке
    деталировки подсвечивает деталь в 3D. Детали, которых нет в деталировке (профиль купе), помечаются.
